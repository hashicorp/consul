```release-note:bug
connect: When the mesh `TLSMinVersion` is `TLSv1_3` and `TLSMaxVersion` is unset or `TLS_AUTO`, Consul now sets the Envoy maximum TLS version to TLS 1.3. Previously, Envoy upstream connections defaulted to a TLS 1.2 maximum and every handshake failed with `NO_SUPPORTED_VERSIONS_ENABLED`.
```

```release-note:bug
connect: The automatically injected post-quantum key-exchange list for TLS 1.3 is now `X25519MLKEM768, X25519, P-256` for Envoy and agent TLS, so peers that only support P-256 keep working after an upgrade. Explicitly configured `ECDHCurves` and `tls_ecdh_curves` are unchanged.
```

```release-note:improvement
connect: Writing a mesh config entry whose new or changed `TLS.Outgoing.ECDHCurves` omits `P-256` while TLS 1.2 can be negotiated is rejected, because service mesh certificates use ECDSA P-256 keys and such handshakes fail with `WRONG_CURVE`. Incoming lists and unchanged stored or bootstrapped entries produce a warning instead.
```

```release-note:improvement
connect: Writing `ECDHCurves` in the mesh config entry is rejected while any server in any WAN-federated datacenter runs a version older than 2.1.0. Servers log a warning listing agents in the entry's admin partition that are older than 2.1.0 and ignore the setting, and the leader reports their count in the `consul.mesh.pqc_outdated_agents` gauge.
```
